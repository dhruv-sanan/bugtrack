# BugTrack Frontend Implementation Plan

**Goal:** Build the frontend specified in `specs/2026-11-04-bugtrack-design.md` on top of the finished Express API.

**Architecture:** App Router client pages behind a client-side guard. RTK Query owns server data and the current user. Filters live in the URL. `shared/permissions.ts` decides what the UI shows.

**Order:** scaffold, move backend, deploy and smoke test, then frontend. The API is only re-tested here, not re-built.

## Design

**Subject:** a triage tool. The one physical object in this world is the ticket itself, so the ticket is the signature.

**Signature, the ticket stub:** cards have a priority-coloured stub on the left, split from the body by a perforation line with punched notches, and the key (`BUG-12`) printed vertically in mono. The stub is the drag handle, so the signature does real work. It repeats on the login page, where each demo account is a stub to tear off. Everything else stays quiet.

Stub rules from the Fable review:

- Keys reach 15 characters, so the card has a min-height and the stub truncates, with the full key in `title`.
- Keep a small grip glyph, on draggable cards only, so people find the handle. Add `aria-label="Move BUG-12"` and `KeyboardSensor`.
- Print the key with `writing-mode`, not rotation. Cut notches with a CSS mask so they stay correct on any background and in `DragOverlay`.
- The handle sits outside the card's link. `/tickets` shows no drag styling.
- Always show priority as text on the card too, so it is never colour alone.

| Token | Value | Use |
|---|---|---|
| Ink | `#141B2D` | Text, sidebar |
| Paper | `#EDF0F5` | Page background, cool carbon-copy grey |
| Card | `#FFFFFF` | Surfaces |
| Rule | `#D5DBE5` | Borders, perforation |
| Carbon | `#2438C9` | Primary actions and focus, carbon-paper blue |
| High / Medium / Low | `#D9342B` / `#E8A317` / `#24786E` | Priority stubs, triage-tag colours. Stub text is white on High and Low, ink on Medium, all above 4.5:1 |

**Type:** Familjen Grotesk for headings, Instrument Sans for body, JetBrains Mono for keys and counts.

**Status glyphs:** a circle fills up as work advances (empty, half, three-quarter, check), so the icon encodes real progress.

**Quality floor:** responsive to 360 px, visible focus rings, `prefers-reduced-motion` respected. Light theme only, cut for speed.

## Tasks

3. **Shared components:** badges, stub, filter bar, user select, confirm dialog, empty state, ticket form.

Commit after each task group. Verify in the browser against the deployed API contract before moving on.

## Traps to handle

- **401 loop:** `resetApiState` on 401 must skip `auth/me` and `auth/login`. Otherwise `me` refetches, gets 401, resets, and loops. A failed login is also a 401 and must show the form error instead.
- **Guard:** only a 401 from `me` means logged out. A 500 or network failure shows a retry, not a redirect.
- **Switching users:** `resetApiState` on login and after the logout response, then `upsertQueryData('me')`, so one user's cache never shows to the next. Resetting before the response lets `me` refetch with a still-valid cookie.
- **204 responses:** logout and deletes have no body, so unwrap with `r?.data`.
- **Stale tickets:** removing a member and deleting a user or project all change tickets, so those mutations also invalidate ticket tags.
- **Return path:** the guard redirects to `/login?next=<path>`, so an emailed ticket link survives login. Accept only same-origin paths: one leading `/`, not `//`.
- **New signups:** a fresh Developer has no projects. The empty state explains that an Admin or Manager must add them to a project.
- **Per-card gating:** disable drag and the status dropdown unless `canEditTicket`. Otherwise every disallowed drag looks like a bug.
- **`/users`:** gate on `canManageUsers`. Managers get 200 from `GET /users`, so an API error will not stop them seeing the page.
- **Users table:** disable role and delete on your own row and on demo accounts.
- **Next 16 `params`:** it is a Promise, so client pages use `useParams()`.
- **Pickers:** the global create dialog needs a project picker with `limit=200`, since the default is 20. Clear the assignee when the project changes. The add-member picker uses `q` search and leaves out existing members.
- **Empty filters:** omit empty values from API calls, because `status=` returns 400.
- **Optimistic board update:** patch every cached ticket list through `selectInvalidatedBy`, not only the current args. Roll back all patches on failure.
- **Radix Select:** an empty string value throws. Use the sentinels `all` and `none`, and translate at the URL and API boundary.
- **Radix dialog from dropdown:** opening a Dialog or AlertDialog from a DropdownMenu can leave `pointer-events: none` on `body`. Use `modal={false}` on those menus.
- **Developer create and edit:** the API returns 403 for a non-null `assigneeId` on create and for any reassign on edit, so hide the assignee field on create and make it read-only on edit unless `canAssignOrDeleteTicket`.
- **Ticket edit:** PATCH changed fields only. Empty diff means no request.
- **Assignee options:** come from `GET /projects/:id/members`, because Developers get 403 on `GET /users`. Global `/tickets` therefore offers only the "assigned to me" filter.
- **Board filters:** hide the status filter on the board, since columns already show status. Keep it in list view.
- **Null people:** null reporter shows "Deleted user", null assignee shows "Unassigned".
- **Bad URLs:** non-numeric IDs and 403/404 responses render an empty state with a way back, never a crash.
- **`useSearchParams`:** wrap in `<Suspense>` or `next build` fails.
- **`.env` upload:** the Vercel CLI does not read `.gitignore`. Add `.vercelignore` with `.env` before the first deploy.
- **Vercel protection:** smoke test the production alias, since generated deployment URLs may sit behind Vercel Authentication.
- **Region:** run the function in the same region as Neon, set through `regions` in `vercel.json`. One status PATCH runs at least five statements, so a distant database would make every board action feel slow.
- **Production env checklist:** `DATABASE_URL`, `DIRECT_URL`, `JWT_SECRET`, `APP_URL`, and the SMTP values. An empty `APP_URL` fails `z.url()` and makes every authenticated route return 500, because `env()` validates everything at once.
- **Reseed last:** the smoke test adds users and uses up IDs, so reseed production just before submitting.
